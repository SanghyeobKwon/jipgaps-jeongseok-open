## Design Specificity Verdict

### LLM assessment

구조는 분명히 집값의 정석을 위해 설계됐지만 시각 언어는 아직 범용 Apple/SaaS 분석 도구에 가깝다. `전국 → 시·도 → 시·군·구 → 읍·면·동 → 건물`, 행정경계, 평형 보정, 표본 부족 표기는 제품 고유성이 강하다. 반면 흰 카드, 검정 선택, 블루 CTA의 반복은 다른 금융 대시보드에도 그대로 적용할 수 있다. 대표 장면이어야 하는 지도가 작은 윤곽과 충돌하는 라벨 때문에 가장 덜 정교하게 보이는 것이 가장 큰 문제다.

### Deterministic scan

`detect.mjs --json app/page.tsx`는 exit 0, finding 0으로 깨끗했다. 그러나 실제 브라우저에 주입한 detector는 홈 20개, 지도 17개, 차트 20개, 임장 19개의 anti-pattern 요약을 출력했다. headless 콘솔 요약에는 개별 rule 이름이 포함되지 않아 CLI 0건과 같은 규칙 집합으로 합산하지 않았다.

### Visual overlays

가변 script 주입은 성공했고 detect.js도 네 대표 화면에서 실행됐다. 다만 이 환경은 사용자에게 보이는 브라우저 탭을 제공하지 않아 신뢰할 수 있는 `[Human]` 오버레이가 존재한다고 주장할 수 없다. 대신 1440×1000과 390×844의 실제 geometry, console, 스크린샷을 근거로 판단했다.

## Overall Impression

밝고 신뢰감 있는 부동산 의사결정 도구의 뼈대는 좋다. 하지만 핵심 약속인 지도와 차트에서 현재 가장 큰 시각적·기능적 골짜기가 생긴다. 가장 큰 기회는 화면을 더 꾸미는 것이 아니라, 지역 선택을 한 번으로 줄이고 지도 자체를 정확하고 안정적인 대표 장면으로 복구하는 것이다.

## What's Working

- `map-path`와 지역 선택 흐름은 전국에서 한 동까지 좁히는 제품 모델을 명시적으로 보여준다.
- 표본 부족, 공식 원천, 추정 한계, 감정평가가 아니라는 고지가 일관돼 고위험 부동산 판단 도구에 적합하다.
- 데스크톱 검색기의 우선순위와 넓은 단일 표면은 빠르게 스캔되며, 지도 HTML 조작 버튼은 대부분 44px 기준을 만족한다.

## Priority Issues

### [P0] 핵심 데이터 실패가 복구 불가능한 빈 화면으로 보인다

- **Why it matters**: `/api/trades`와 `/api/overview`가 모든 대표 화면에서 502를 반환한다. 사용자는 무자료인지 설정 오류인지 구분하기 어렵고 차트·순위·요약 작업을 완료할 수 없다.
- **Fix**: watchlist·차트·요약을 하나의 명시적 오류 상태로 묶어 원인, 영향 범위, `다시 시도`, `다른 지역 보기`를 제공한다. 실패 상태에서 0을 정상 집계처럼 표시하지 않는다.
- **Suggested command**: `$impeccable harden`

### [P1] 지도 축척과 라벨 체계가 실제 공간 이해를 방해한다

- **Why it matters**: 모바일 SVG가 폭 122%, 좌측 -11%로 배치돼 패널 양쪽 약 24px가 잘린다. 22개 라벨 중 절반을 숨기고 나머지를 20px로 키워 실제 겹침이 발생한다. 데스크톱에서도 680px 표면 안의 국토 윤곽이 지나치게 작고 긴 행정명과 `집계 중`이 글자 파편처럼 보인다.
- **Fix**: 실제 패널 폭 안에서 지도 윤곽이 65–75%를 차지하도록 projection 자체를 다시 fit한다. 전국 단계는 짧은 지명만 표시하고 수치는 선택·호버·보조 패널에서 보여준다. `nth-of-type` 기반 임의 숨김을 제거하고 경계 크기·우선순위·충돌 검사를 기준으로 라벨을 결정한다. 선택 지역은 채움, 외곽선, 요약 패널을 함께 갱신한다.
- **Suggested command**: `$impeccable adapt`

### [P1] `#map` 공유·새로고침 진입이 화면 중간에서 시작한다

- **Why it matters**: 데스크톱은 `scrollY=346`, 모바일은 `scrollY=621` 상태로 진입해 지도 제목, breadcrumb, 선택기가 화면 위로 잘린다. 사용자가 “지도가 이상해졌다”고 느끼는 가장 직접적인 원인이다.
- **Fix**: 초기 hash 동기화가 끝난 뒤 해당 화면의 시작점으로 scroll을 정규화하고, 뒤로가기·새로고침에서도 같은 규칙을 적용한다.
- **Suggested command**: `$impeccable harden`

### [P1] 모바일 내비게이션과 주요 조작의 접근성이 약하다

- **Why it matters**: 390px에서 7개 상단 메뉴 중 약 5개만 보이고 `커뮤니티`, `정책`은 수평 스크롤 뒤에 숨는다. 차트 기간/보기 버튼은 높이 약 29px로 44px 기준을 충족하지 못한다.
- **Fix**: 모바일을 핵심 4개 탭 + `더보기` 또는 실제 하단 탭으로 재구성한다. 차트 탭과 select를 모두 44px 이상으로 올리고 safe-area와 키보드 초점을 검증한다.
- **Suggested command**: `$impeccable adapt`

### [P2] 중복 선택과 작은 글자가 인지 부하를 높인다

- **Why it matters**: 홈 검색 직후 지도에서 같은 시·도·구·동을 다시 선택한다. 지도·순위·임장 곳곳의 7–12px 텍스트는 DESIGN.md의 본문 13px 기준과 충돌한다. 임장 모바일은 실제 작업 영역이 첫 844px 아래에서 시작한다.
- **Fix**: 홈 선택을 지도에 그대로 이어 `범위 변경` 하나만 남긴다. 본문·조작 라벨은 13–14px, 보조 메타는 11–12px로 올린다. 임장 모바일의 상태 요약과 단계 선택을 접거나 한 줄로 줄여 실제 결과를 첫 화면 안에 노출한다.
- **Suggested command**: `$impeccable distill`, `$impeccable typeset`

## Cognitive Load

8개 항목 중 5개가 실패해 높은 인지 부하다.

- 실패: single focus — 홈 검색기와 지도 직접 선택기가 연속 노출된다.
- 실패: visual hierarchy — 차트 오류가 큰 빈 그래프 중앙의 작은 문장으로 끝난다.
- 실패: one thing at a time — 경로, select 3개, 지도 도형, 전국 순위를 동시에 판단한다.
- 실패: minimal choices — 상단 메뉴 7개, 주택 유형 6개, 인기 지역 6개, 임장 분류/시간대/소음원이 한꺼번에 보인다.
- 실패: progressive disclosure — 모바일 임장에서 결과보다 단계·분류·상태 설명이 먼저 한 화면을 차지한다.
- 통과: chunking, grouping, working memory.

## Emotional Journey

- 진입은 밝은 표면, 명확한 검색 CTA, 공식 데이터 표현 덕분에 차분한 신뢰를 만든다.
- “전국에서 생활권까지”라는 문구가 통제감과 기대를 높인다.
- 지도에 들어가면 작은 윤곽, 잘린 화면, 겹친 지명이 기대를 크게 꺾는다.
- 차트의 API 오류와 큰 공백이 두 번째 골짜기를 만든다.
- 임장의 `LIVE/BETA/DATA CONNECT`와 실측 전 수치 비노출 원칙은 신뢰를 회복한다.
- 그러나 실제 데이터가 아닌 `82점 · 추천` 샘플이 경고보다 강하게 보이면 다시 신뢰가 흔들린다.

## Persona Red Flags

### Alex — Power User

- 지도, select, 전국 순위가 같은 지역 선택을 반복한다.
- 최근 지역, 즐겨찾기 재진입, 키보드 단축 경로가 없다.
- API 실패 시 다른 지역이나 대체 데이터로 우회할 수 없다.

### Sam — Accessibility-dependent

- SVG 지역은 키보드를 지원하지만 16개 이상의 도형을 선형 순회해야 하고 라벨은 겹치거나 임의로 숨겨진다.
- canvas 차트에는 월별 데이터를 읽을 수 있는 표나 텍스트 대안이 없다.
- 7–10px 텍스트와 색에 의존하는 상승·하락 표현이 저시력·확대 환경에 취약하다.

### Casey — Distracted Mobile User

- 주요 메뉴가 상단 수평 스크롤 안에 있고 일부가 보이지 않는다.
- 잘린 지도와 겹친 라벨로 작은 지역을 정확히 누르기 어렵다.
- 검색 직후 같은 지역을 다시 선택해야 한다.
- 임장 결과가 첫 viewport 아래에 있어 현재 작업을 바로 확인할 수 없다.

## Minor Observations

- 상승 빨강·하락 파랑은 한국 금융 관습과 맞지만 색 외에 부호와 텍스트를 항상 병행해야 한다.
- 긴 공식 행정명은 select와 지도에서 축약 규칙이 필요하다.
- 지도 우측 순위 패널은 로딩 중 공백이 너무 커 지도와의 연동감이 약하다.
- `마우스를 움직여 월별 상세 확인`은 모바일·키보드 사용자를 포함하지 않는 문구다.
- quick-region chip과 일부 주택 유형 탭도 실효 높이가 44px보다 작다.

## Questions to Consider

- 대표 장면이 지도라면, 왜 지도보다 선택기와 빈 표면이 더 많은 공간을 차지해야 하는가?
- 전국 지도에서 동시에 읽어야 하는 것은 16개 지명과 수치 전부인가, 변화가 큰 3–4개 지역인가?
- 홈 검색과 지도 선택을 하나의 연속 동작으로 만들면 몇 번의 중복 선택을 없앨 수 있는가?
- 실측 전 숫자를 만들지 않는 제품 원칙과 `82점 · 추천` 샘플은 같은 신뢰 기준을 충족하는가?
